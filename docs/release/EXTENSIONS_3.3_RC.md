# FileWorkbench Next 3.3 RC — 操作・復元・プレビュー拡張

2026-10-07 / hiro1960 / MIT。3.2 RCの構造を維持した修正済みソース一式。
本追補が現在の実装説明。過去の資料にある未実装の機能を実装済みとは扱わない。

## 追加した機能

| 領域 | 実装 |
|---|---|
| ごみ箱・復元 | 独立したrecycleモジュール。Windowsごみ箱と退避履歴を別タブで表示 |
| ごみ箱検索 | 名前・元の場所・ドライブ・削除日時の開始／終了（空欄で全期間） |
| 復元 | 選択、復元先チェック、元の場所／任意の場所、同名時別名／スキップ、実保存先表示 |
| ファイル操作 | コピー・移動・複製・ごみ箱移動。コピー後内容照合、上書き防止、結果とCSVログ |
| 退避 | 移動／ごみ箱処理前に実データを退避・照合。欠落／改変データからの復元を拒否 |
| 右クリック | プレビュー、名前変更画面、情報、既定アプリ、保存場所、パス・HASHコピー、ファイル操作、選択操作 |
| 画面固有メニュー | tree出力、rename候補更新、compare再比較、hash CSV出力、preview前後移動、recycle復元・表示情報 |
| DD | 各情報ビューと対象入力へローカルファイル／フォルダー。出力・復元先の専用欄はフォルダーのみ |
| 選択 | 各一覧でCtrl個別選択、Shift範囲選択、右クリック全選択／解除。プレビュー本文は通常の文字選択 |
| 切り離し | User Modeの全6コンテンツで別窓と元画面への復帰。Developer Modeの既存組み込み・単体表示も維持 |
| 出力先 | tree／HASHに明示的な出力先欄。ファイル操作・復元は処理前と結果に保存先表示 |
| 操作配置 | 対象選択、出力、メディア、切り離し等の主操作を下方へ配置。検索・条件は上部 |
| 背景処理 | ファイル操作、走査、HASH、比較、ごみ箱検索／復元、HASHコピーをワーカーで実行 |

### プレビュー対応表

| 形式 | 表示・操作 |
|---|---|
| Qtが読める画像 | フィット表示、GIFアニメーション |
| PDF | ページ画像、ページ送り |
| TXT／JSON／CSV／ソース等 | 本文、先頭1MiBまで、UTF-8／UTF-16／CP932の順で試行 |
| DOCX／PPTX | 本文の簡易表示。書式・図形・元レイアウトの再現は含まない |
| XLSX | 先頭10シート、各200行×20列の値の簡易表示 |
| ZIP | 内容一覧。自動展開・実行は行わない |
| 音声・動画 | Qtメディアの再生／一時停止／停止／音量。ドラッグとクリックによるシーク |
| その他 | 名前・拡張子・サイズ・場所。既定アプリへの入口 |

再生対応は実際のコーデック／メディアに依存する。すべてのファイルを再生できる保証ではない。
音声と動画は同じPlaybackPortを使う。シークバーは0〜10000を実際の再生時間へ換算。
プレイヤーのseekableに合わせて操作可能にする。停止、ファイル切替、閉じる際にソースを解放。
右クリックからの移動・ごみ箱処理前にはRouterがPreview I/Fのreleaseを呼ぶ。
処理後に消失ファイルを除去し、対応する一覧をrefreshする。

## ごみ箱と退避の安全な扱い

- 通常の削除はごみ箱への移動。移動も「コピー・照合後に元をごみ箱へ」の順で行う。
- ごみ箱・移動の前に退避データと署名を保存。退避失敗／照合失敗時は元を変更しない。
- Windowsごみ箱の一覧／復元はShell APIを使用。ごみ箱管理ファイルを直接編集・削除しない。
- Shell復元は選択した復元先の一時退避フォルダーへ戻し、内容を照合して最終先へ上書きせずコピー。
- Shell処理の完了が確認できない場合は失敗扱い。一時退避場所を表示し、そのデータを残す。
- 復元後の一時退避も安全のため保持。復元先に`.fwn_restore_...`フォルダーが残る。
- 退避履歴からの復元は実データのコピー。Windowsごみ箱にある同一項目を自動削除しない。
- 履歴は記録、退避は復元用実データ。履歴だけでは復元できない。
- 退避メタデータに保護と30日の保持目安を記録。本版は自動削除しない。
- 永久削除、退避データの削除／世代整理、最新3世代＋7日保持の自動管理は今回未実装。
- キャンセルは項目間で反映。実行中の1項目は安全に終了するまで待つ。
- ファイルコピー途中の失敗では元を残し、部分的な出力が残る場合は結果の保存先を確認する。
- リンク／ジャンクションはファイル操作対象から除外。親子を同時選択した場合は親だけ処理。
- 処理中は元データを他APPで編集しない。複数APPで同じ退避領域を同時利用する排他制御は未実装。

## I/Fと再利用

### UIモジュール

従来どおりModulePort、ModuleContext、ModuleEvent、EventBus、ModuleBoxを維持。
I/Fで対応コマンドを明示。Descriptorのcommandsもmodule.jsonから生成。
previewはplay / pause / stop / seek / releaseを公開。seekのvalueは0〜10000。
recycleはsearch / restoreを公開。restoreは選択状態と確認画面を使用する。
preview.requested / rename.requestedで他モジュールからの表示要求を配送。
files.will_change / files.changedでファイルロックの解放と表示の再確認を行う。

### 共通サービス

| I/F | 実装 | 役割 |
|---|---|---|
| FileOperationsPort | FileOperationsService | Qtから独立したファイル操作・退避・照合・履歴・復元 |
| RecycleBinPort | WindowsRecycleBin | Windows Shellのごみ箱一覧・復元 |
| PlaybackPort | QtPlaybackService | 再生・停止・シーク・ソース解放。UIは呼び出し側が持つ |
| PreviewReaderPort | Text／Office／Archive／MetadataReader | 本文・一覧の安全な簡易読み取り |

他APPにはsrc/fileworkbenchをパッケージとして取り込み、必要なI/Fだけをimportする。
ファイル操作の保存領域はAPPごとにFileOperationsService(root=...)で明示する。
共通UIのModuleWidget.serviceも別のFileOperationsPort実装へ差し替え可能。
UIを使う場合はassetsも配置する。配布可能な独立wheel化は今後の作業。
examples/reuse_file_service.pyとexamples/reuse_preview.pyを同梱。

## 起動と確認

1. 新しいフォルダーへZIPを展開し、scripts/setup_environment.batを実行（pywin32はWindowsのみ）。
2. start_app.batを起動。対象フォルダー／ファイルを各ビューへDD。
3. Ctrl・Shiftで選択し右クリック。各種ファイル操作はテスト用のコピーで確認する。
4. プレビューへ画像、PDF、テキスト、音声、動画をDDし、下部の操作を確認。
5. 各コンテンツ下部の「別窓で開く」→「元の画面へ戻す」を確認。
6. ごみ箱・復元の一覧更新。Windowsごみ箱と退避履歴の入口を混同しない。
7. 選択→復元先指定→復元先チェック→実行→結果に表示された実保存先を確認。
8. scripts/run_tests.bat、scripts/build_release.batで試験とEXE生成。

## 設計上の推奨

処理を共通サービス、入力解釈を各I/F、操作表示を各UI、配送をRouterへ分けて維持する。
プレビュー形式を追加するときは専用Reader／再生実装を追加し、対応表と試験を更新する。
危険な操作を共通メニューへ無条件に追加しない。ごみ箱項目には通常ファイルの削除メニューを使わない。
出力先と結果の保存先を両方表示し、失敗・スキップを成功と混ぜない。

## 追加依頼の反映：共通対象・ソート・条件設定・保守モード

### 共通対象と個別対象

画面下部に共通対象欄を追加。複数ファイル選択、フォルダー選択、DDが可能。
各コンテンツの「共通対象を使う」で参加／個別を切り替える。
初期状態はpreviewのみ共通参加し、従来のtree選択→preview連携を維持。
他のコンテンツは初期状態で個別。共通から個別へ戻すと、その前の個別対象を復帰する。
コンテンツへ直接DDや対象選択をした場合は自動的に個別指定へ切り替える。
明示的な右クリックのプレビュー／リネーム要求も受信側を個別指定へ切り替える。
共通入力が対象形式に合わない場合はmodule.errorを表示し、無理に処理しない。
共通配送中にtree選択イベントが発生しても再配送しないガードを入れた。
TargetPolicyPort / SharedTargetPolicyはQtに依存せず他APPにも再利用可能。
共有設定と列幅の全コンテンツ横断の永続保存は今後の拡張（rename既存列幅保存は維持）。

### 一覧と比較

全結果一覧の全列をInteractiveへ統一。列境界をドラッグして幅変更できる。
見出しクリックで昇順・降順ソート。数値は数値順で比較する。
セル更新中はソートを停止し、行のパス・サイズ・HASH・状態が混ざらないようにする。
通常ファイルの一覧・ツリーからURL形式でドラッグ可能。コンテンツ間で入力としてDDできる。
これは入力の転送であり、DDしただけでコピー・移動・削除を実行する操作ではない。
Windowsごみ箱の内部項目には通常ファイルのドラッグ／破壊的メニューを使わない。
比較はフォルダー同士に加え、ファイル同士のサイズ・内容比較に対応。
左右の対象欄もドラッグ元になり、反対側や他コンテンツへDDできる。
「⇄ 左右を交換」ボタンも用意。左右の種類が異なる場合はエラーを表示。
名前・パス・状態等のフィルターを維持し、退避履歴にも検索を追加。
treeのフィルターは一致する子の祖先を表示し、親が隠れて結果が見えなくなる問題を修正。

### リネーム

ライト: 検索・置換、接頭辞、接尾辞。
詳細: 正規表現、大小文字区別、空白除去、文字種変換、拡張子変更・対象拡張子の限定、連番、日付。
連番の開始・桁数・先頭／末尾・区切りを指定できる。
日付は更新・作成(OS情報)・現在から選択し、形式と先頭／末尾を指定。
詳細条件はライトでは適用しない。詳細へ戻すと設定は保持。
連番は入力パスの並びで決定し、表示ソートでは変更しない。
「選択行だけ実行」を追加。変更前後のプレビューと実行件数・候補確認を経て実行。
実行前に退避・照合し、上書きしないrenameを行い、各結果と退避履歴を記録。
途中失敗は成功した項目と失敗した項目を結果に残す。完全な一括ロールバックは未実装。
RenameRules / build_planはQtから独立した条件エンジン。
I/Fのconfigureコマンド、またはContext.options.rename_rulesから条件を渡せる。
例: {"numbering":true,"start":1,"digits":3,"mode":"advanced"}。
書き換え対象はベース名、拡張子は既定で維持。番号・日付の追加順は番号→日付。
退避履歴からの復元はコピー復元であり、現在のリネーム先を自動削除するUndoではない。

### Developer / Maintenance

「組み込み試験」「別窓で開く」は登録済みPortの同じWidgetを利用する。
「単体ウィンドウ」はcreate_port(module_id)で独立したI/Fインスタンスを作る。
独立単体試験のイベントは監視ログへ記録するが、登録済みモジュールへ自動配送しない。
契約試験も独立インスタンスで実施し、通常の試験対象の入力状態を消さない。
必須操作、Widget、空Contextの受信・返却、context.received、コマンド宣言一致、未対応拒否、二重終了を確認。
「保守診断」でPython／OS／依存関係／モジュールの版・対応コマンド・読み込みエラーを表示。
「診断・ログ保存」でJSONとして保存。既存の同名ファイルは上書きしない。
イベントは直近1000件を保持。ログを共有する際は個人のパス等の内容を確認する。

追加分の検証: 共通指定・個別復帰・列幅・祖先フィルター5件と、命名条件・選択実行・比較交換・数値ソート・独立起動・契約試験7件。
最終自動試験は合計46件成功。Windows実機の未確認項目は前掲のとおり。
